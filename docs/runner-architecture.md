# Подключение рабочей среды: GitHub + runner

Статус на сейчас: кабинет хранит только записи проектов и статические отчёты аудита. Исходники не хранятся, команды не выполняются, сборка и запуск — «не проверено».

## Принцип

Источник истины для кода — GitHub-репозиторий. Кабинет (Poehali) только хранит метаданные и показывает результат. Всё, что исполняет код, живёт вне Poehali, на отдельном runner.

```
Кабинет (Poehali)  <-- HTTPS, токен -->  Runner (ваш ПК или сервер)
  проекты, отчёты                          git, npm, Docker, preview
        |                                          |
        +------------ GitHub (репозиторий) --------+
```

## Часть A. Только файлы и Git (без выполнения команд)

Можно сделать первой. Рисков исполнения чужого кода нет.

| Функция | Что нужно |
|---|---|
| Привязать репозиторий к проекту | URL репозитория, ветка |
| Список файлов и чтение файла | GitHub API, токен с правом чтения |
| Показ истории коммитов | GitHub API |
| Показ diff между коммитами | GitHub API |
| Создание ветки и коммита с правкой файлов | Токен с правом записи (лучше fine-grained, на один репозиторий) |
| Pull request вместо прямого коммита | GitHub API |
| Скачивание ZIP репозитория и повторный аудит | GitHub API + существующий аудитор |
| Откат (revert-коммит) | GitHub API |

Где живёт: backend-функция кабинета. Токен GitHub хранится только в секретах, в базу и в отчёты не попадает. Правки ИИ на этом уровне — это предложенный набор изменений файлов, который вы просматриваете и подтверждаете; ИИ ничего не запускает.

## Часть B. Нужно выполнение команд (только runner)

| Функция | Почему нужен runner |
|---|---|
| Установка зависимостей (npm/bun install) | Исполняет скрипты пакетов |
| Сборка (npm run build) | Исполняет код проекта и плагины |
| Запуск dev-сервера и предпросмотр | Долгоживущий процесс, порт |
| lint, typecheck, тесты | Исполняют код проекта |
| Запуск backend-функций локально | Исполняют код проекта |
| Применение SQL-миграций к тестовой базе | Нужны доступ к базе и исполнение |
| Скриншот страницы | Нужен браузер |
| Подтверждение статуса «сборка проходит» | Только по факту выполнения |

## Протокол кабинет ↔ runner

Runner сам обращается в кабинет (исходящее соединение). Входящие порты на вашем компьютере открывать не нужно.

1. Кабинет создаёт задание: `{id, project_id, repo, ref, команды из аудита, тип: install|build|dev|test}`.
2. Runner раз в несколько секунд запрашивает следующее задание, подписав запрос своим ключом.
3. Runner клонирует репозиторий в чистую рабочую папку или контейнер, выполняет команды и шлёт обратно журнал (без значений секретов), код возврата и время.
4. Кабинет записывает результат и только тогда меняет статус: «установка / сборка / запуск: выполнено» или «ошибка». До этого везде «не проверено».

Нужны новые таблицы: `runner_jobs` (задание, статус, журнал, коды возврата) и `runners` (имя, хэш ключа, последний сигнал). Это отдельная миграция следующего этапа.

## Требования безопасности к runner

- Каждое задание в отдельном Docker-контейнере, удаляется после выполнения.
- Лимиты CPU, памяти и времени; контейнер без доступа к вашей домашней сети и без ваших личных файлов.
- В контейнер передаются только секреты, явно указанные для проекта; на первом этапе — никаких production-ключей и production-базы.
- Список разрешённых команд берётся из подтверждённых вами полей проекта, а не из текста ИИ.
- Журналы фильтруются: значения из переменных окружения заменяются на `***`.
- Ключ runner отзывается из кабинета; задания без подписи отклоняются.

## Порядок внедрения

1. Часть A: привязка GitHub, чтение файлов, повторный аудит по репозиторию. Результат: кабинет видит реальный код без ZIP.
2. Минимальный runner на вашем компьютере: только install + build, один проект, вручную запускаемый. Результат: впервые появляется честный статус «сборка проходит».
3. Preview: dev-сервер на runner, доступ по туннелю или с вашего сервера.
4. ИИ-агент: предложения правок в ветке (часть A) + проверка их на runner (часть B) + pull request.
5. Только потом: несколько пользователей, облачные контейнеры, публикация.

## Что остаётся вне Poehali всегда

Runner, Docker, терминал, npm/Git на сервере, живой предпросмотр чужого проекта, публикация на внешний хостинг.
