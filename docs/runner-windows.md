# Установка runner: Windows 10 Home 22H2 (сборка 19045)

Подготовлено под ноутбук ASUS VivoBook 17 (Intel Core i3-6006U, 2 ядра / 4 потока, 16 ГБ ОЗУ, SSD 466 ГБ + HDD 932 ГБ). Всё нужное есть, но процессор слабый: сборки будут идти медленнее, чем на современном компьютере (ожидайте минуты, а не секунды). Видеокарта не нужна.

Схема: **WSL2 + Ubuntu + Docker Engine внутри WSL**. Docker Desktop не нужен. Python уже входит в Ubuntu, на Windows его ставить не надо.

Runner сам обращается в кабинет. Открывать порты не нужно.

## Этап A. Подготовка (ничего не устанавливается)

1. **Виртуализация.** Диспетчер задач (Ctrl+Shift+Esc) → Производительность → ЦП. Внизу должно быть «Виртуализация: Включено». Если «Отключено», её включают в BIOS (Intel VT-x); для ноутбука ASUS обычно: перезагрузка с нажатой F2 → Advanced → Intel Virtualization Technology → Enabled. Без этого WSL2 не заработает.
2. **Место на диске C:.** Проводник → Этот компьютер. На диске C: (там будет WSL) нужно минимум 20 ГБ свободно. Пришлите, сколько у вас свободно на C:.
3. **Обновления Windows.** Windows 10 снята с обычной поддержки в октябре 2025 года; обновления безопасности приходят только по программе расширенной поддержки (ESU). Проверьте в «Параметры → Обновление и безопасность», что обновления подключены. Компьютер будет выполнять чужой код в контейнерах, поэтому важно, чтобы система была обновлена.

## Этап B. WSL2 и Ubuntu

PowerShell **от имени администратора** (правый клик на Пуск → Windows PowerShell (администратор)):

    wsl --install -d Ubuntu

Перезагрузите компьютер. После перезагрузки откроется Ubuntu: задайте имя пользователя и пароль (это пароль Linux, он не связан с Windows; запомните его, он нужен для `sudo`). Проверка в PowerShell:

    wsl -l -v

В столбце VERSION должна стоять цифра 2. Если там 1: `wsl --set-version Ubuntu 2`.

Если установка зависает на «Загрузка» или Microsoft Store недоступен: сначала `wsl --update`; если не помогло, пришлите сообщение об ошибке, подберём способ.

Ограничьте ресурсы WSL, иначе он займёт до половины памяти. В Проводнике откройте `C:\Users\ВАШЕ_ИМЯ\` и создайте файл `.wslconfig` (Блокнот, имя файла с точкой в начале, тип «Все файлы»):

    [wsl2]
    memory=6GB
    processors=3
    swap=2GB

Затем в PowerShell: `wsl --shutdown`, и снова откройте Ubuntu.

## Этап C. Docker Engine в Ubuntu

Все команды вводятся в окне Ubuntu.

    sudo apt-get update
    sudo apt-get install -y ca-certificates curl gnupg python3
    sudo install -m 0755 -d /etc/apt/keyrings
    curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
    echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list
    sudo apt-get update
    sudo apt-get install -y docker-ce docker-ce-cli containerd.io
    sudo usermod -aG docker $USER

Закройте окно Ubuntu, откройте заново. Если `download.docker.com` недоступен из вашей сети, поставьте пакет из репозитория Ubuntu: `sudo apt-get install -y docker.io` (и тогда после установки: `sudo usermod -aG docker $USER`).

Если Docker не запущен: `sudo service docker start`. Проверка:

    docker version

Должны быть выведены и Client, и Server. Если Server не виден, Docker не запущен.

## Этап D. Образ Node.js

    docker pull node:20-bookworm-slim

Это официальный образ с Docker Hub. В мае 2024 года Docker Hub на несколько дней блокировал российские адреса, затем доступ вернули; нынешнее состояние у вашего провайдера нужно проверить этой командой.

Если команда не проходит (таймаут, 403):
- **не** подключайте случайные зеркала из интернета: из образа исполняется код, подменённый образ получит доступ к вашему проекту и токену;
- **не** отключайте проверку TLS и не используйте `insecure-registries`;
- допустимо: зеркало вашего провайдера или организации, которому вы доверяете (только `https://`, в `/etc/docker/daemon.json`), либо перенос образа: на компьютере, где Docker Hub доступен, `docker save node:20-bookworm-slim -o node20.tar`, перенести файл и выполнить `docker load -i node20.tar`; идентификатор образа (`docker image ls --digests`) должен совпасть на обоих компьютерах.

## Этап E. Тестовый проект на GitHub

Для первой проверки не берите боевой проект. Используйте готовый минимальный:

1. Скачайте архив `studio-runner-sample.zip` (лежит на сайте проекта по адресу `/studio-runner-sample.zip`) и распакуйте.
2. На GitHub создайте **отдельный публичный репозиторий** `studio-runner-sample` (кнопка «+» → New repository, галочку README не ставьте).
3. Откройте «uploading an existing file», перетащите **содержимое** распакованной папки (файлы `package.json`, `package-lock.json`, `index.html`, `tsconfig.json`, `vite.config.ts`, `.gitignore` и папку `src`), нажмите Commit changes.
4. В кабинете откройте проект, вкладку «Репозиторий» и подключите `ваш-логин/studio-runner-sample` (публичному репозиторию токен не нужен).

Для публичного репозитория токен GitHub не требуется ни кабинету, ни runner.

## Этап F. Runner

1. Скачайте `studio-runner.zip` (`/studio-runner.zip` на сайте проекта), распакуйте. Скопируйте папку в Ubuntu: откройте в Проводнике `\\wsl$\Ubuntu\home\ВАШ_ЛОГИН\` и вставьте туда папку `runner`. Не запускайте runner из `/mnt/c`: там всё работает медленнее.
2. В кабинете: проект → «Сборка» → «Создать ключ». Ключ показывается один раз. Скопируйте его в надёжное место.
3. В Ubuntu:

        cd ~/runner
        cp config.example.json config.json
        chmod 600 config.json
        nano config.json

   Адрес кабинета `cabinet_url` уже вписан в пример; замените только `runner_key` на ключ из кабинета. `github_token` оставьте пустым. Сохранение в nano: Ctrl+O, Enter, Ctrl+X.
4. Проверка:

        python3 runner.py --check

   Ожидается: Docker работает, образ есть, кабинет доступен, ключ принят.
5. Запуск:

        python3 runner.py

   Runner ждёт задания. В кабинете: «Новая сборка» → поставьте галочку подтверждения → запустите. В Ubuntu runner покажет репозиторий, коммит и команды и спросит `[y/N]`; введите `y`.

Остановка runner: Ctrl+C (контейнер будет остановлен).

## Что считать успехом первого запуска

Все пять пунктов сразу:
1. В кабинете и в консоли один и тот же короткий SHA коммита и он совпадает с последним коммитом в вашем репозитории на GitHub.
2. Установка зависимостей завершилась с кодом 0.
3. Сборка завершилась с кодом 0.
4. В результате `dist` примерно 2 файла, около 150 КБ.
5. Статус в кабинете относится именно к этому заданию.

Если что-то не так, это нормально для первого настоящего запуска: пришлите вывод `--check` и журнал задания, разберём причину. Скрипты установки (`allow_scripts`) и ослабление ограничений автоматически не включаются.

## Что делает runner для безопасности
- Скачивает архив строго по полному SHA. Подлинность проверяется дважды: имя корневой папки заканчивается на короткий SHA, и полный SHA совпадает с комментарием ZIP, который записывает GitHub. Это защита от ошибок и случайной подмены; скачивание идёт только по HTTPS с серверов GitHub. Архивы с `../`, ссылками и «бомбами» отклоняются.
- Ключ runner даёт право только забирать задания и отправлять по ним результат. К паролю кабинета, проектам, токенам GitHub и базе доступа нет. Отозванный ключ перестаёт работать сразу: runner останавливает контейнер.
- При отмене, таймауте, Ctrl+C или отзыве ключа контейнер принудительно останавливается командой `docker kill`.
- Только команды из белого списка: `npm ci`, `npm install`, `pnpm install --frozen-lockfile`, затем `npm|pnpm run build`.
- Установка по умолчанию с `--ignore-scripts`.
- Контейнер без привилегий (`--cap-drop ALL`, `no-new-privileges`), файловая система только для чтения, лимиты памяти, процессов и CPU, один том с проектом, без Docker socket и домашней папки.
- **Сборка идёт без сети.** Установка зависимостей идёт с сетью.
- Журнал очищается от токенов и ключей до отправки в кабинет.
- Переменные окружения и production-секреты в контейнер не передаются.

## Ограничения
- Docker снижает риск, но не гарантирует безопасность. Подключайте только свои репозитории.
- Переменные `VITE_*` пока не передаются: проект, которому они нужны при сборке, может не собраться.
- Монорепозитории не поддерживаются: сборка идёт из корня.
- Образы и пакеты скачиваются из внешней сети: доступность зависит от вашего провайдера.
